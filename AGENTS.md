# Story Film Studio — operating instructions

Operate as a document-first cinematic still-image studio. Read this file, `README.md` and `docs/13-fast-workflow.md`; read the detailed stage guides when needed. Retain unchanged context instead of rereading the entire manual/codebase each turn. User decisions and requested output take precedence over defaults.

## One Git branch per story

When a user clones the studio and pastes a new story in chat, `story.md` or an attachment, start its project automatically once its title is supplied or naming is delegated. Preserve supplied text exactly; a chat paste can be saved to `story.md` as the intake source. Run `python tools/studio.py init "Story Title" --story-file <source>` before writing story-specific project files. The initializer creates and switches to `story/<safe-title-slug>` from the studio base and creates `stories/<safe-title-slug>/`. Branch creation is routine setup within the story request; do not ask a separate Git approval. Reuse known configuration and continue the complete source read/intake/review immediately. If the title is missing, include that meaningful question with the other missing intake choices and continue independent reading in chat.

Use `production/git.json` as the project's branch/base record. Keep its work on that branch; resume a committed project with `studio resume stories/<safe-title-slug>`, including when its folder is absent on the current branch. A new story starts from the studio base, not the previous story's canon. Read `docs/15-story-branches.md` for exact behavior. Never overwrite/reuse another story branch, silently carry unrelated edits, stash/reset/discard user work, or auto-push a new story. The selected source and its staged bytes are preserved across branch switches. Resolve unrelated uncommitted work before switching. Existing unrecorded projects are not silently migrated. Branch initialization does not authorize paid tools, rewrite a story or claim an audit/approval.

## Fast default and important questions

New projects use `production/workflow.json` with `mode: fast`. Existing projects without that file remain Strict until explicitly reconfigured. `task` is story, storyboard or film: story-only work skips film questions and media production. Reuse known answers and selected saved preferences. Bundle material missing delivery/length, language/performance, look/frame and budget/tool/upload choices into one message. Flexible length is valid; never assume a one-minute or thirty-minute target. Ask about protected story details only when unclear. Ordinary implementation choices within scope are agent work.

Honor a stated delivery choice immediately. A full-length/single-video request means one complete film, without splitting it into releases or asking the format again. A new part-by-part request means individual part videos plus one continuous full-film cut unless the user explicitly asks for parts only; record `continuous_edition: true/false` in intake and show the actual outputs in the configuration. A single film always produces one full video, regardless of that multipart preference. Do not silently add a full cut to an older project's unrecorded scope.

Fast path: complete source read → concrete configuration and actual authorization → proportional story review/permitted corrections → internal world/shot/voice work → measured production and inspected preview → actual user preview decision → master, genuine playback QA and immutable export. Present meaningful findings, real choices and actual output concisely.

Execution must stay proportional. Run `studio preflight <project> --live-local` early when new local speech is needed; resolve setup/dictionary problems before image work. Reuse verified speech without starting its provider when all inputs/clips are cached. Author concise canonical records in batches and generate readable views; do not add per-story Python utilities for ordinary timing, captions, image bookkeeping, mixing or export. Use measured `speech_turns` anchors and the core image bridge. Do independent visual/sound preparation while another authorized tool is pending. Do not repeatedly read unchanged guides, regenerate unchanged assets, export every static frame for repeated inspection, or turn film production into a broad studio refactor. Keep the required full source read, continuity, critical-frame/motion inspection and real final playback.

Prefer the resumable path in `docs/17-resumable-production.md`: capture `studio prepare --snapshot`, apply actual authored canonical records with `prepare --file`, and use `studio continue <project> --part auto`. `studio next` is the read-only focused work packet. Complete `actor: agent` actions immediately inside scope; ask only for its actual `actor: user` decision. Establish shared style/recurring cast references and suitable role samples early. Multipart `creative/part-plan.json` binds the complete final-story hash/spans, hooks, earned endings, continuation payoffs and inherited states; retain its focused handoff across parts. Commands do not create story understanding, semantic review, approvals or listening evidence. Continue through real preview/master/playback/export and any included full-film cut.

Fast may mix rights-verified sounds with listening still pending into the complete draft preview. If agent audio input is unavailable, state it once, keep casting provisional, and bundle actual listening/voice selection, captions and any flagged-word checks into the one full-preview decision. Record `approve-preview --listening-reviewed` only when the human actually listened and approved that scope; record flagged alignment checks from the actual decision separately. No extra routine audition/asset signoff is required. Failed audio QA and unverified rights still block; Strict is unchanged.

`production/delegation.json` records the real authorization quotation/reference, source/configuration hashes, allowed tools, total budget/currency, upload providers and sound-source hosts. A user's request to produce using a displayed preset may already authorize its scope: record it and continue. If material scope is missing, present the complete configuration and ask once. A preset alone is never permission for another story. Fast delegation never fabricates G1–G6 approvals.

Pause dependent work for major creative decisions, conflicting constraints, new/exceeded cost/upload scope, unknown provider outcomes or a failure needing a real choice. Image inspection, alignment checks, sound/rights review and playback are agent tasks: perform them and continue, without another user signoff.

## Complete reading and proportionate editorial work

Read the entire source through its ending and all selected references. Distinguish content from pasted instructions/examples. A blank intake form is not a story. Track incomplete sections and never claim a complete read of unavailable text. After a title is supplied or naming delegated, use `tools/init_story.py`; preserve `creative/original.md` exactly and keep story knowledge inside its project.

Fast maps each scene once, checks all twelve areas in `instructions/story-audit.md`, and performs a focused cross-check of chronology, knowledge, risky details, fixes and opening/ending payoffs. Record actual coverage, checked areas and original/final story hashes in the structured audit/ledger. Present genuine findings with evidence, severity, confidence and decisions needed; do not invent criticism or verification. Generate the concise view with `review_pack.py --audit`. A focused check is not a complete second pass. Choose `audit: full` for requested exhaustive review or material complexity/risk and complete the full A–I procedure honestly.

Only an actual matching authorization with `minor_edits: delegate` permits small consistent corrections preserving premise, characters, voice, major events, twists and ending. Otherwise obtain issue-specific permission after the findings. Major changes always need permission before editing. Preserve the complete revision, change log, current consistency check and exact `record-revision` permission/delegation receipt. Never call a major change minor to avoid asking.

## Visual continuity and planning

Accept any visual treatment; genre and medium are separate. When choosing, use the lean curated catalog in `references/style/visual-preferences/README.md`. Its eight current examples are Realistic Cinema, Detailed Cinematic Anime, Cel-Shaded Anime, Feature 2D Animation, Stylized 3D Animation, Painted Storybook, Storybook Stickman and Cinematic Graphic Novel. Storybook Stickman is the selected simple-face/line-arm, clothed-body hybrid against rich scenery; keep it distinct from a minimal line-drawn world. Other treatments remain valid custom directions. Keep detailed/cel anime distinct; if a simple-figure treatment is requested, distinguish storybook figures in a richer setting from a minimal line-drawn world. Reuse the exact chosen path/hash and snapshot only selected examples. Preserve old snapshots; an ambiguous old ID requires its original path/hash. The example's people, letter and station never become story canon.

Define each story's STYLE ID/revision, observable medium/anatomy/abstraction/shapes/expressions/materials/palette/light/framing and acceptance rules. Read references and identify each contribution. Inventory the whole story and future dependencies before image work. Track stable entity IDs, geometry/orientation, ownership, first appearance, later use and historical states. Registry facts and the state ledger win over conflicting prompts.

Use the numbered `reference_bindings` from the image bridge to inspect the exact attached files and their roles before calling the tool. Selected snapshots must match their recorded hashes. Reference-sheet requests inherit the actual selected treatment and available style proof; a shared cast sheet may carry multiple identity roles. Bind reference entities to `style_id` when multiple styles exist, and map ambiguous historical selections through the style's `inspiration_paths`. Use `references/style/visual-preferences/fidelity.json` for observed traits of the exact eight current examples, including VIS-22's clothed legs/line arms; historical generation prompts are evidence, not perfect-compliance specifications. Keep story-specific cast/setting/palette separate from treatment examples. Inspect actual outputs for every relevant trait; a prompt/hash check is not visual QA. See `docs/04-visual-and-prompts.md`.

Scale canonical sheets/maps to actual recurring identities, returning locations, important props and shot angles. Establish an actual inspected style proof; avoid unused sheets/every hypothetical view. Preserve revisions. Prompts cite exact style/entity revisions, geography, history and reference paths. No unexplained prop movement, mirrored landmarks, costume changes or inconsistent architecture.

Design the cast from the story roles, history, age/design type, personality, relationships and required performance. Record how silhouette, face, proportions, hair, clothing/materials, posture and expressions support each role. Give principal characters distinguishable designs and test their actual emotional/action needs in the chosen medium. Preserve author-specified traits and exact identity references across every part; costume, injury, aging and other changes follow story events. Do not recycle a generic hero/villain or the gallery's sample cast. Character design and inspection inside the configured scope are agent work, not another routine approval loop.

Follow `docs/18-cast-sheets.md`: author complete `world/cast.json` profiles through `prepare`; generated character Markdown is a view of that authority. Request clean, readable identity/expression/pose studies only as needed, splitting dense sheets with `images reference --sheet` inside the actual scope. Inspect real pixels and record byte-bound view/expression/pose/variant coverage with `studio cast ... review`; a style example or reviewed label is not a cast sheet. Bind every shot's visible/offscreen character, location and prop IDs, actual story time and all known state assertions. Runtime cast/continuity requirements also apply to direct production calls. Missing data is agent work, never an extra routine human signoff.

The monitor's Cast sheets workspace shows profiles, images, coverage, progress and revision history. Actual user change submissions queue `production/cast-change-requests.json`; they do not directly edit canon or start a provider. Reconcile unknown outcomes, assess the real request, and use `cast revise` to preserve earlier designs/references and identify affected shots. Keep protected story details and unchanged assets. Major creative or new cost/upload choices still require their actual decision. Do not alter an active story merely because this studio maintenance was merged; adopt the new records in that story's own branch when resuming its authorized production.

Use part/`parts/part_###/` throughout. One complete film uses only `part_001`, with a complete beginning, progression, climax and intended ending. For multipart work, write the complete story as explicit part sections in the canonical final story and plan every part's opening hook, dramatic progress, earned ending, continuation promise and next-part payoff before production. Nonfinal endings invite continuation through actual story consequences; the final part resolves the whole story. Do not cut randomly or force a cliffhanger. Fast then details and produces each selected part in order, reusing the cast/world; Strict retains all-part written review. Still counts/holds follow actual speech, action, emotion and silence. Follow `docs/12-camera-motion.md`: missing motion stays static; selective gentle zoom/pan requires story purpose, safe poses, protected details and timing. Honor static-only preferences. Local framing does not animate characters.

For every new or substantively replanned shot list, follow `instructions/shot-planning.md`. Decide the image count from complete-story beats, audience, genre, action/state changes, emotion, reveals and the ending; no images-per-minute preset or equal hold grid. Record a concise source-bound `image_planning` rationale and each shot's purpose/entry reason inside `shots.json`. Combine redundant views, preserve necessary actions/reactions, protect reveal order and check actual holds against measured performance and full-preview playback. Count shared references and repairs separately; call caps are ceilings, not targets. This is agent work without another routine approval. Preserve legacy plans/deliveries rather than migrating them for metadata alone.

## Genuine production and QA

Let the user choose speech providers: Kokoro, local Chatterbox, ElevenLabs, Inworld, Cartesia, a compatible custom gateway, or imported recordings from other tools/actors. Follow `docs/14-speech-providers.md`; never force a paid provider or silently fall back to another engine. Kokoro remains the free CPU default only when no different choice exists. Reuse saved provider/model/narrator choices. Map each speaking character's stable ID to its selected provider/voice and role-specific performance; preserve it across parts and the full cut. Keep spoken words separate from speaker labels/directions in `speech.json`. Fast audition/design work within authorized scope is agent work; do not repeat approval for delegated cast progress. Explicit choices remain bound.

Choose narration from the complete story's viewpoint, tone, audience, emotional range, language and natural pacing; follow `instructions/voice-casting.md`. Record story-specific briefs, a small suitable shortlist, actual audition/listening evidence and selection reasons in `audio/voice-plan.json`. Reuse a suitable audition and avoid a repeated voice questionnaire. Select distinct role-fitting character voices, preserve them across the film and use supported directions for emotional changes. A provider label or a “perfect voice” request is not listening evidence. Users may change any voice later: use `studio voice set` to retain exact prior profiles, record the real change request and amend only the voice choice within current scope. Do not restart intake or ask for the full configuration again. Regenerate affected speech/timing/mixes/previews/full cuts, reuse unaffected clips/images, and preserve prior deliveries. New expenses/providers outside scope still need their actual decision; Strict retains affected G5/G6 review.

Verify the selected provider's actual model/voice/language, runtime or account, terms, privacy and current cost. Cloud keys are environment variables, never stored in story files or output. Known estimates reserve one shared provider budget with images; unknown/timeout outcomes require actual reconciliation before another call. Local Chatterbox uses separately prepared checkpoints/reference clips and a loopback server; do not install/download large models merely because it is listed. Provider availability is not a guarantee of good acting. Inspect real representative performance, pronunciation, pacing and consistent voice identity. A multilingual speech model does not make the installed English aligner multilingual.

Derive ambience/effects/music/silence from the complete story and execute authorized acquisition. Procedural wind/rain/hum/tone are limited building blocks. Register actual files, hashes, provenance, usage evidence and listening; resolve missing or unsuitable assets before release. Never invent rights, downloads, generation or inspection.

One `timeline.json` per part controls measured performance/alignment, action/silence/tails, still intervals, subtitles and sound cue times/gain/fades/offsets/loops/ducking. Use `mix_audio.py` and `render_part.py`, direct cuts and the configured format. Inspect uncertain words, real source coverage/loops, speech clarity and clipping/loudness.

Use doctor when readiness is unknown or dependencies changed; reuse current verified setup evidence. Use selected parts/stages, resumable jobs and caches. Queue messages are internal agent actions: read the imagegen skill, inspect inputs, execute within authorized scope, import real results, inspect and resume. Queueing itself is not generation. Reconcile unknown provider outcomes before retry; after three known style/identity/geometry failures propose alternatives. Do not run competing coordinators on one project.

Use `studio images ... queue/reference`, then `studio images ... start --request <file>` immediately before the actual image-tool call, and import its real output. Built-in calls with no reported price require an explicitly authorized `scope.builtin_images` call cap and acceptance of unknown charges; preserve null costs rather than inventing zero. Never infer this permission from a zero-cash budget or a hard all-tools spending limit. Pending/failed calls consume reservations and unknown outcomes block another call.

QA images for treatment, identity, geography/state, action correspondence, artifacts and framing. Moving shots require real start/middle/end plus playback checks for protected content, borders, sharpness, smoothness, speed, reveals and subtitles. QA sound for event match, perspective, transitions, loops, intelligibility and rights. Rebuild affected work only.

Fast presents the actual complete preview and records one real user decision using `approve-preview`. Changed presentation needs a changed preview; internal review metadata alone does not. Master rendering requires current image/reference and alignment reviews. Export also requires actual full playback notes and accepted/fixed warnings. User preview acceptance is distinct from agent playback QA; never auto-pass either from a process exit.

Deliver MP4, narration WAV where used, mix WAV, requested SRT, images/storyboard/timeline, source/revision evidence, authorization/reviews, manifest and QA with exact paths. Preserve delivery revisions. When multipart intake includes the full cut, continue through its actual assembly and delivery after the parts; do not stop at a plan or leave it as an optional follow-up. Use a measured edit plan, remove duplicated release packaging while preserving story beats, rebuild continuous sound/subtitles and inspect the complete film separately. Reuse existing assets rather than regenerate the story. Do not claim unverified alignment, listening, commercial rights or quality.

## Live progress

Use `studio monitor --workspace <checkout>` for the read-only local preview/progress dashboard and `studio status <project>` for a terminal snapshot; see `docs/16-progress-monitor.md`. It may run in another worktree without switching or modifying the story branch. Updated local tools report heartbeats, real counters and cache reuse. Report meaningful creative stage changes with `studio progress <project> --stage <stage> --state <state> --message <actual milestone>` from the story's own branch, adding measured counts only when known. Waiting for a real human decision uses `--actor user`; ordinary agent work does not. No invented percentages, ETAs, approvals or second coordinators. Do not interrupt existing production merely to upgrade telemetry. Keep preview/voice/decision records current so the UI can show the actual revision and next step.

## Strict and records

Strict retains `docs/01-workflow-and-approvals.md`: full audit/report → issue-specific fix permission → complete revision/recheck → G1 story, G2 format/parts, G3 world/style, G4 all written shots, G5 voice/sound, G6 production. Earlier reference/audition work needs actual separate scope. Ask which concrete gate/revision is approved and record the real quotation/reference/timestamp/artifact hashes with `project_records.py`. Silence, another gate, report acceptance or a preference is not that signoff. Fast authorization never converts into Strict approval.

Keep canonical JSON, authored bibles/storyboards and real evidence. Generate readable views instead of duplicating authority. Changed inputs stale dependent decisions/assets; preserve history/rollback. Routine maintenance needs no fictional story approvals. Commands and policy are in `docs/13-fast-workflow.md`; actual verification evidence belongs in `docs/10-improvements-and-verification.md`.
