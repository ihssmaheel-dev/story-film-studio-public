# Story intake and video requirements

> **Fast policy:** Read `docs/13-fast-workflow.md` first. Reuse saved preferences and actual sufficient authorization. Ask missing material configuration together; story-only tasks skip video questions. Gate references below describe Strict. Fast plans whole-story dependencies and can detail the selected part progressively.

Read the supplied story completely first. Treat a pasted instruction prompt as instructions, not as the author's screenplay. Start the story audit using `instructions/story-audit.md`; ask the missing production questions early while continuing independent audit work. Reuse information already supplied and avoid a long repeated questionnaire.

Once the title is supplied or naming delegated, automatically initialize with `tools/studio.py init "Title" --story-file <source>` before writing story project records. This creates/switches to `story/<safe-title-slug>` and preserves the source in its matching project. A clone-and-paste story request already covers that routine branch setup; do not add a Git approval question. Follow [story branch rules](../docs/15-story-branches.md), resume the existing branch for the same story, and continue intake/review with known answers. An unrelated dirty checkout is preserved and must be resolved before switching.

## First questions after a story arrives

Ask a compact initial batch, adapting to what is already known:
1. Ask **one complete video** or **part-by-part videos** only if the user has not already chosen. “Full-length video” means a single complete film. For a new part-by-part request, include individual videos and a continuous full-film cut in the displayed configuration; honor an explicit parts-only request without asking again.
2. For one video, what total duration do you expect? For parts, what approximate duration or range should each part have, is there a desired part count/total runtime, and may lengths vary with the story? An explicit "recommend a length" or "flexible" is valid; present a justified recommendation instead of assuming a default.
3. Who is the audience, which language should be used, and should delivery be narration-led, dialogue-led, mixed, or without speech? Reuse a named speech provider/voice. When undecided, show local/free and cloud/account options from `docs/14-speech-providers.md`; the user may choose Kokoro, Chatterbox, ElevenLabs, Inworld, Cartesia or another gateway/import route. Bundle provider, budget/privacy and important casting preferences with the existing configuration questions; do not insist on a paid service. Speech-free films skip provider questions.
4. What visual style and delivery format do you want (landscape, portrait, square or specified dimensions/platform)? Which supplied references apply? Where material and unanswered, offer static framing or selective gentle camera moves chosen for the story; reuse the user's existing answer.
5. What sound approach do you want: ambience, sound effects, music and/or deliberate silence? May the studio generate sounds, source suitable licensed assets, use provided files, or combine these? Record budget and external-upload restrictions before dependent tool calls.

Bundle related questions and offer sensible choices. Ask about the title, whether the story/ending is complete, protected details, tone, intended emotional impact and content preferences only where not already clear. Explain a missing fact when it materially blocks a decision. Offer a recommendation with reasoning when the user asks for guidance.

Treat an unset narrator/character voice as delegated casting inside the selected provider/language/scope, not another routine questionnaire. Follow [voice casting](voice-casting.md): read the complete story, record its performance brief, reuse a suitable known audition or compare a small actual shortlist and listen. Users can change voices later without restarting intake; preserve explicit choices until a real change request and record that scoped choice with `studio voice set`.

For the visual-style question, show the [eight-look comparison board](../references/style/visual-preferences/comparison-sheet.png) or [curated gallery](../references/style/visual-preferences/README.md) when useful. Offer the actual distinct treatments: Realistic Cinema, Detailed Cinematic Anime, Cel-Shaded Anime, Feature 2D Animation, Stylized 3D Animation, Painted Storybook, Storybook Stickman and Cinematic Graphic Novel. Accept a descriptive name/stable ID, refinement or custom direction; do not add a collection-version choice. Genre, mood, palette and detail can be tailored independently. Reuse existing choices and snapshots, including retired examples. An old ambiguous ID requires its stored path/hash before interpretation. Record exact file/SHA-256, chosen name/ID and role `visual treatment only`, with manifest hash/Git provenance internally. Snapshot only selected material. The comparison scene's actors, letter and station never become the user's story canon. Story-specific designs still require the actual internal/Strict review for the configured workflow.

## Record decisions in creative/intake.json

Use the JSON record as the authoritative answer set; `tools/review_pack.py` generates `creative/intake.md` as its readable view. See `docs/11-story-to-film-journey.md` for the user-facing sequence and question map.

Include the story source/hash, completeness, title agreement, format mode, per-part/total duration, flexible vs hard constraints, desired count, audience, language, voice approach, style/references, frame dimensions/aspect/fps, subtitle preference, sound sourcing/generation permissions, budget/privacy constraints and preserved creative choices. Record `unanswered`, `user specified`, or `proposed` explicitly; never mark a proposal approved automatically.

`mode: single` always delivers one complete film. New intakes set `continuous_edition: true`; this preference applies only to `mode: parts`, adding the continuous full-film cut to the individual videos. Use `false` for an explicit parts-only choice. Missing/null in an older project does not add an unrequested full cut; confirm scope only if material. Preserve this preference in presets and bind it to the configuration authorization.

If no title is agreed, keep the audit/intake in chat, ask for a title when material, and persist everything after `tools/init_story.py` is used. Do not create an invented story project just to store an intake form.

## Stage decisions so the review can proceed

Missing format/duration affects runtime/split recommendations, not the ability to identify contradictions. Finish the rest of the audit and label runtime uncertainty. Final mode, duration policy, part scope and boundaries must be decided by G2; exact recorded performance determines final timing. Style locks at G3, narration/visuals/sound intent at G4, voice/sound approach at G5, and production tools/costs/privacy at G6.

One complete video uses only `parts/part_001/`, with a complete story and intended ending. Part-by-part videos use as many `part_###/` folders as the story needs. Write the entire multipart narrative in explicit part sections before media production; map each opening, local arc, earned ending, continuation promise and its next-part payoff. Produce parts in order, then the configured continuous edition. Use "part" in user-facing plans, filenames, manifests and tools. There is no fixed one-minute runtime, still count, or forced cliffhanger. Choose image count and duration from the action, emotional beats, narration/dialogue and intentional silence. The full cut reuses the same cast/assets and needs its own measured edit, continuous audio/subtitles and real playback QA; its inclusion is part of configuration, not a new routine authorization request.

The production method remains cinematic still-image video. Optional local zooms/pans frame the stills; `camera_motion` records `static`, `selective` or null, and the exact per-shot plan requires G4 review. Missing shot motion stays static; see `docs/12-camera-motion.md`. Generated character/object motion is a different scope: discuss available tools before promising it. Never infer character animation from an anime/3D visual style or from a longer duration.
